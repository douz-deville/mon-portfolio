INITIUM – Durcissement du Socle Réseau & Identité (Phase 1)

Guide d'implémentation complet pas-à-pas : segmentation réseau VLAN, pare-feu pfSense, annuaire Active Directory et politiques de sécurité.

Auteur : AGBOGAN Kossi Christian Daniel Esuté
Organisation : CHR HEALTH-CENTER (ESIV)
Version : 1.1

1. Contexte, Menaces & Objectifs

À la suite d’un audit de sécurité, le Centre Hospitalier Régional HEALTH-CENTER a révélé des vulnérabilités structurelles majeures : absence de segmentation (réseau "plat"), présence de systèmes d'exploitation obsolètes non isolés, défaut de contrôle des accès administratifs et absence de traçabilité.

Le projet INITIUM pose les fondations d'un socle réseau et d'identité étanche et résilient. L'objectif est d'appliquer le principe du moindre privilège au niveau des flux et de l'annuaire avant l'intégration ultérieure d'outils de détection avancés.

1.1 Projet 1 : "INITIUM – Durcissement du Socle Réseau & Identité"

Cette première phase pose les fondations indispensables de la nouvelle infrastructure. Aucun outil de supervision ou de détection avancée n'est déployé à ce stade : on se concentre sur l'étanchéité et le contrôle des accès.

1.2 Objectifs et Compétences Techniques

  • Sécurité Périmétrique et Routage Contrôlé : Segmenter un réseau plat par le déploiement d'un pare-feu open source (pfSense) et la configuration de réseaux virtuels (VLANs) étanches.
  • Application du Principe du Moindre Privilège : Concevoir, documenter et appliquer une matrice de flux inter-VLAN stricte (blocage par défaut, autorisation exclusive de l'existant légitime).
  • Centralisation et Durcissement de la Gestion des Identités (IAM) : Déployer un annuaire d'entreprise (Active Directory) sain, structuré par rôles métiers, et y appliquer des stratégies de sécurité restrictives via GPO (Group Policy Objects).
  • Prise en compte des contraintes sectorielles (Santé) : Isoler concrètement le segment Biomédical sensible contenant des protocoles non chiffrés (DICOM/HL7), une problématique propre aux architectures hospitalières.

2.2 Périmètre Technique du Projet 1 (Sur EVE-NG)

Pour valider techniquement ce socle sans surcharger les ressources physiques, le laboratoire se limitera aux briques suivantes :

Sécurité Périmétrique :

  • 1x Instance pfSense unique (la Haute Disponibilité CARP sera traitée au Projet 2).
  • 4x VLANs ciblés au lieu du modèle global.

Gestion de l'Identité & Systèmes :

  • 1x Contrôleur de Domaine (Windows Server 2022) : Rôle AD DS pour le domaine health-center.com. Création des Unités Organisationnelles (OU) médicales et administratives.
  • GPO de durcissement initial : Stratégie de mots de passe forte, verrouillage automatique de session, blocage des périphériques de stockage amovibles (USB).
  • 1x Poste Client (Windows 10/11) : Placé dans le VLAN ADMIN, intégré au domaine, servant de témoin pour valider la descente des GPO et le routage.
  • 1x Équipement Biomédical Virtuel (Linux léger) : Placé dans le VLAN 50 pour valider l'étanchéité du réseau biomédical.

3. Étape 1 : Création du point d'accès externe (Cloud0)

Avant de poser la moindre machine, nous devons créer la porte d'entrée qui relie le laboratoire au monde extérieur. Dans EVE-NG, cela se matérialise par un réseau de type "Nuage".

  1. Faisons un clic droit sur le quadrillage blanc d'EVE-NG ➜ Sélectionnons Network.
  2. Dans la fenêtre de configuration qui s'ouvre :
    • Name/Prefix : Effaçons le texte par défaut et tapons WAN_Internet.
    • Type : Choisir impérativement Management(Cloud0) dans le menu déroulant.
  3. Clique sur Save.

Pourquoi fait-on cela ?
Ce nuage Management(Cloud0) est directement relié à la première carte réseau (eth0) de EVE-NG, celle que nous avons configurée en mode NAT dans Virt-Manager. C'est ce nœud qui va accomplir deux rôles critiques : donner un accès Internet au pare-feu pour ses futures mises à jour, et permettre d'ouvrir l'interface graphique du pfSense depuis le navigateur du PC hôte.

4. Étape 2 : Déploiement du nœud pfSense et câblage

Maintenant que la porte de sortie existe, nous installons le pare-feu périmétrique.

  1. Ajout du Node : Faire un clic droit sur le quadrillage ➜ Node ➜ Sélectionner pfSense. Laisser les paramètres par défaut (2 interfaces, RAM à 1024 ou 2048 MB) mais passer de 'telnet' à 'vnc' et cliquer sur Save.
  2. Câblage de la patte Internet : Survoler le pfSense pour attraper l'icône de prise orange, puis glisser le câble vers le nuage WAN_Internet. Dans la fenêtre qui s'ouvre, choisir impérativement l'interface em0 du côté pfSense, et Cloud0 du côté du nuage. Valider.

5. Étape 3 : Initialisation dans la console pfSense

Allumer le pfSense en faisant un double-clic dessus et ouvrir sa console textuelle. Laisser le système charger jusqu'à ce qu'il pose les questions d'attribution des cartes.

Voici la configuration exacte à saisir :

  • Should VLANs be set up now [y|n]? Répondre n (Non). Nous allons créer les VLANs proprement depuis l'interface web, ce sera beaucoup plus simple et visuel pour la suite.
  • Enter the WAN interface name : Taper vtnet0 et valider. (L'interface em0 devient ainsi officiellement la patte externe connectée à Internet).
  • Enter the LAN interface name : Appuyer directement sur Entrée sans rien écrire. (C'est normal : nous n'affectons pas de LAN classique puisque nous allons découper l'interface em1 en plusieurs VLANs logiques par la suite).
  • Do you want to proceed [y|n]? Taper y (Oui) et valider.
  • Would you like to remove the LAN IP address and unload the interface now [y|n]? Taper y (Oui) et valider.

Le pfSense va terminer son initialisation et afficher son menu principal. Sur la ligne de l'interface WAN (wan), il va indiquer l'adresse IP qu'il a récupérée (dans notre cas : 192.168.122.146/24).

6. Étape 4 : Premier accès à l'interface graphique (WebGUI)

Une fois l'adresse IP WAN attribuée par l'hyperviseur, l'administration du pare-feu s'effectue depuis le navigateur web du poste hôte.

  1. Ouvrir un navigateur web sur le PC physique.
  2. Saisir l'adresse IP obtenue par le pfSense dans la barre d'adresse (ex: https://192.168.122.146).
  3. Ignorer l'avertissement de sécurité lié au certificat SSL auto-signé en cliquant sur Paramètres avancés puis sur Continuer vers le site.
  4. Saisir les identifiants de connexion initiaux par défaut :
    • Username : admin
    • Password : pfsense
  5. Cliquer sur Sign In.

7. Étape 5 : Configuration initiale via l'assistant (Wizard)

Au premier accès, un assistant de configuration s'ouvre automatiquement pour structurer les paramètres système fondamentaux de l'infrastructure hospitalière.

7.1 Identification et DNS du Système

  • Hostname : Taper pfsense-fw (Nom réseau du pare-feu).
  • Domain : Taper health-center.lan (Domaine de l'organisation, en évitant le TLD .local pour prévenir les conflits de protocoles mDNS/Apple).
  • Primary DNS Server : Saisir 10.0.60.10 (Adresse IP planifiée pour le futur contrôleur de domaine Active Directory du VLAN 60, indispensable pour la résolution interne).
  • Secondary DNS Server : Saisir 1.1.1.1 (Serveur DNS public pour maintenir la résolution externe en cas de maintenance du serveur interne).
  • Override DNS : Décocher la case pour interdire au DHCP d'EVE-NG d'écraser ces paramètres statiques.
  • Cliquer sur Next.

7.2 Synchronisation Horaire (NTP)

  • Time server hostname : Laisser pool.ntp.org (Garantit une synchronisation parfaite des horloges, condition critique pour la corrélation des logs et les équipements biomédicaux).
  • Timezone : Sélectionner Europe/Paris (ou le fuseau adapté).
  • Cliquer sur Next.

7.3 Configuration de l'interface WAN

  • Configuration Type : Laisser sur DHCP.
  • Laisser tous les blocs de configurations statiques ou spécifiques (PPPoE, PPTP) vides.
  • RFC1918 & Bogon Networks : Décocher impérativement les deux cases Block RFC1918 Private Networks et Block bogon networks.

    Pourquoi fait-on cela ? Si ces options restent cochées, le pare-feu bloquera tout trafic provenant de plages d'adresses privées. L'adresse du poste physique et le réseau NAT de Virt-Manager étant en zone privée (RFC1918), cocher ces cases couperait immédiatement l'accès à l'interface graphique du lab.

  • Cliquer sur Next.

7.4 Sécurisation du compte d'administration

  • New admin Password : Saisir Hosp-Initium2026!.
  • Confirm admin Password : Saisir Hosp-Initium2026!.
  • Cliquer sur Next puis sur Reload pour appliquer la configuration.

Une fois le rechargement terminé, le pfSense affiche son tableau de bord complet (Dashboard).

8. Étape 6 : Raccordement du pfSense au switch virtuel Trunk

Pour que le pare-feu puisse router le trafic des différents services de l'hôpital, sa seconde interface doit être connectée au commutateur virtuel en mode Trunk (agrégation de liens).

  1. Arrêt propre de la VM : Dans la console Termius du pfSense, saisir l'option 0 (Shutdown system) et valider par y. Attendre que le nœud devienne gris (éteint) sur le schéma EVE-NG.
  2. Ajout du nuage interne : Faire un clic droit sur le quadrillage d'EVE-NG ➜ Network :
    • Name/Prefix : Trunk_Hosp
    • Type : Choisir Management(Cloud1) (qui correspond au switch virtuel / pont réseau créé dans Virt-Manager dédié au trafic interne).
  3. Cliquer sur Save.
  4. Câblage de l'interconnexion : Glisser le câble depuis l'icône orange du pfSense vers le nuage Trunk_Hosp. Sélectionner impérativement l'interface em1 (ou vtnet1) du côté pfSense. Valider.
  5. Relance du système : Faire un clic droit sur le pfSense ➜ Start.

9. Étape 7 : Création des interfaces virtuelles (VLANs) dans pfSense

Une fois le pare-feu redémarré, l'accès à l'interface WebGUI (https://192.168.122.146) permet d'injecter la logique de découpage réseau.

9.1 Accéder au gestionnaire de VLANs

Naviguer dans le menu supérieur vers Interfaces > Assignments, puis cliquer sur l'onglet VLANs tout à droite. Cliquer sur le bouton vert + Add.

9.2 Taguer l'interface parente

  • Parent Interface : Sélectionner impérativement em1 (ou vtnet1).
  • VLAN Tag : Saisir le numéro du VLAN (ex: 10).
  • Description : Saisir le nom du service (ex: VLAN10_MEDIC).
  • Cliquer sur Save.
VLAN Tag VLAN Priority Description
10 0 (Best Effort) VLAN10_MEDIC
30 0 (Best Effort) VLAN30_ADMIN
50 0 (Best Effort) VLAN50_BIOMED
60 0 (Best Effort) VLAN60_SERVERS

9.3 Assigner le VLAN créé

Revenir sur l'onglet Interface Assignments. Dans le menu déroulant Available network ports, sélectionner le VLAN fraîchement créé (ex: VLAN 10 on em1...) et cliquer sur + Add.

9.4 Configurer l'adressage IP

Cliquer sur le nom de la nouvelle interface apparue (souvent nommée OPT1).

  • Cocher Enable Interface.
  • Description : Renommer l'interface de manière explicite (ex: MEDIC).
  • IPv4 Configuration Type : Sélectionner Static IPv4.
  • En bas dans Static IPv4 Configuration : Saisir la passerelle correspondante (ex: 10.0.10.254) avec un masque en /24.
  • Cliquer sur Save puis sur Apply Changes en haut.

Voici le plan d'adressage strict à appliquer pour les 4 interfaces du laboratoire :

MEDIC 10 10.0.10.254 /24 (255.255.255.0)
ADMIN 30 10.0.30.254 /24 (255.255.255.0)
BIOMED 50 10.0.50.254 /24 (255.255.255.0)
SERVERS 60 10.0.60.254 /24 (255.255.255.0)

9.5 Résolution du blocage de l'accès WebGUI (IP WAN)

Après la validation de l'assistant initial, le pare-feu active par sécurité ses mécanismes de protection restrictifs. Dans un environnement de laboratoire virtuel où l'administration s'effectue par la patte externe (WAN), ces protections provoquent un blocage immédiat de l'interface graphique.

Déblocage d'urgence via le Terminal :

  1. Ouvrir la session Terminal du pfSense.
  2. Dans le menu principal textuel, saisir l'option 8 pour ouvrir le Shell.
  3. Saisir la commande suivante pour couper temporairement le moteur de filtrage du pare-feu : 
    pfctl -d

10. Étape 8 : Configuration des serveurs DHCP par VLAN

Dans pfSense, le service DHCP s'active de manière indépendante pour chaque interface réseau locale. Pour notre laboratoire, nous allons l'activer sur les zones clients (MEDIC, ADMIN, BIOMED).

Règle de conception importante : Nous n'activerons pas le DHCP sur le VLAN 60 (SERVERS). Dans une infrastructure critique, tous les serveurs (Active Directory, serveurs de bases de données, etc.) doivent impérativement posséder une adresse IP statique configurée à la main pour garantir la stabilité des services.

Pour les VLANs 10, 30 et 50, naviguer dans le menu supérieur vers Services > DHCP Server et appliquer la configuration suivante :

10.1 Zone Médicale (Interface MEDIC - VLAN 10)

  • DHCP Server : Cocher la case Enable DHCP server on MEDIC interface.
  • Range (Plage d'adresses) : From: 10.0.10.10 | To: 10.0.10.100
  • DNS Servers : Saisir 10.0.60.10 (L'adresse du futur serveur Active Directory/DNS de l'hôpital).
  • Cliquer sur Save en bas de la page.

10.2 Zone Administrative (Interface ADMIN - VLAN 30)

  • DHCP Server : Cocher la case Enable DHCP server on ADMIN interface.
  • Range : From: 10.0.30.10 | To: 10.0.30.100
  • DNS Servers : Saisir 10.0.60.10.
  • Cliquer sur Save en bas de la page.

10.3 Zone Biomédicale (Interface BIOMED - VLAN 50)

  • DHCP Server : Cocher la case Enable DHCP server on BIOMED interface.
  • Range : From: 10.0.50.10 | To: 10.0.50.100
  • DNS Servers : Saisir 10.0.60.10.
  • Cliquer sur Save en bas de la page.
